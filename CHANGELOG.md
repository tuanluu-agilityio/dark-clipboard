# Changelog

All notable changes to Dark Clipboard, newest first. Versions follow [SemVer](https://semver.org/). Sections per release: Added, Fixed, Known issues.

## [Unreleased]

### Added (Phase 3 Windows desktop shell, 0.1.0-alpha internal)
- Task 201: `dark-clipboard` with no flag starts the Slint app hidden (always dark, English and Vietnamese; the OS language is used on first run). Single instance per user: a second start forwards its command over a named pipe restricted to the current user and exits 0. New `--toggle` (show or hide the popup), `--quit` and `--help`; `--headless` is unchanged. The licence is GPL-3.0-only (Slint's GPLv3 option).
- Task 202: tray icon (glyphs generated in code for capturing, paused, private and capture off) with tooltip and menu: Pause (5 minutes, 1 hour, until resumed), Resume, Private mode, History, Settings, Quit. Pause and private mode apply at once.
- Task 203: global shortcut, default `Ctrl+Shift+V` (`shortcuts.toggle_popup`; Ctrl, Alt or Win required). A failed registration shows a warning and is not retried until the setting changes or the app restarts. Hidden test flag `--no-global-shortcut`.
- Task 204: the popup. A frameless, always-on-top dark window opens near the cursor on the monitor under it (per-monitor DPI aware) with the search box focused and recent clips listed, pinned first. Search as you type (accent-insensitive, matched words highlighted); filter chips for kind, pinned, today, 7 days and source app; more clips load as you scroll. Keys: arrows, Page Up/Down, Home/End, Enter copies back, Shift+Enter copies plain text, Delete removes with a 5 second Undo toast, Ctrl+P pins, Alt+1..9 copies the n-th result, Esc or clicking elsewhere closes; every action also has a button. Developer flag `--seed-demo-clips N --data-dir <dir>` writes N synthetic clips (never into the default data folder). Popup open time is logged content-free (`perf`); `scripts/measure-popup.ps1` reports p50/p95.
- Task 205: copy back and paste. Enter puts the clip on the clipboard, closes the popup and returns the focus to the window you were in. Ctrl+Enter also pastes it there (Ctrl+V through `SendInput`); the setting `ui.enter_pastes` ("Enter also pastes", off by default) makes Enter paste too. The paste is never blind: it happens only if the window recorded when the popup opened still exists, belongs to the same process, is a normal visible top-level window (never the taskbar, the desktop or a tool window), takes the focus, and Shift/Alt/Win/Enter are released; otherwise the clip stays copied and a toast says "Copied - paste manually". A target running as administrator gets no input and its own toast. The log records only a coarse `paste` outcome (ok, refused, elevated, failed).
- Task 206: previews and details. Image thumbnails and a detail pane for text (first 32 KiB), images and file lists. Content is read only through UI-only calls that re-check the clip before showing it; masked clips never show or keep content.
- Task 211: history window (tray "History..." or Ctrl+H in the popup): filters (pinned, kind, time, source app), search, multi-select (Ctrl/Shift click, Space, Ctrl+A), copy, copy as plain text, pin, delete with a confirmation, detail pane, size and position remembered per monitor layout, context menu (mouse only).
- Task 207: settings window (General, Privacy, History, About): shortcut, language, start at login, close on focus loss, "Enter also pastes", capture mode (normal, private, paused), retention limits (lowering a limit asks first), excluded apps (built-in entries removable only after a confirmation), a text-only row for the OS and Darkshot privacy markers (not configurable), About with licence notices. One Save for the form. `darkshot.exe` is a built-in Windows exclusion.
- Task 208: first-run welcome. A fresh install captures nothing until the user presses Start; "Not now", Esc or X keep capture off; the tray ("Start capturing...") and Settings reopen the welcome. Existing settings files skip it. Start at login through the `DarkClipboard` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (off by default; never touched by a `--data-dir` instance; an entry disabled in Task Manager is shown as off). `--headless` on a fresh data folder stays off and logs `capture_off`.
- Task 212: on Windows the UI uses Slint's software renderer by default (measured about 12 MiB private bytes after use and no idle CPU, against about 72 MiB and 0.2 % of a core with the GPU renderer). A user-set `SLINT_BACKEND` still wins. The start log records `renderer=software|default|env`. Popup open time (`perf what=popup_shown`) is timed from the first redraw after the show request; a new content-free `perf what=search_done ms=<n>` times a typed search.
- Task 200 (internal): `capture.rs` split into a `capture/` directory, with the privacy checks moved to match.
- Docs: Windows alpha section in the README, user guide `docs/user/windows-alpha.md`, build facts and SHA-256 in `docs/testing/alpha-artifact.md`. No tag or release was made.

### Added (Phase 5 organisation and tools)
- Task 404: local text transforms and edited copies. "Copy as..." (Ctrl+T, or the button) in the popup and the history window shows the result of a transform before you copy it: trim (whole text or each line), line endings (LF or CRLF), UPPER or lower case, JSON pretty or minified (up to 1 MiB, nesting up to 128; keys, numbers and escapes are kept as they are), URL percent-encode or decode, Base64 encode or decode (the decoded bytes must be text), and HTML to text (tags removed, script and style content dropped, common entities decoded, paragraphs and list items become lines). Copying the result writes it to the clipboard as Dark Clipboard's own write: it is not captured again and no clip is stored. Input over 1 MiB is refused, never cut. Images, files and masked clips have no "Copy as...". "Edit..." (Ctrl+E, or the button, history window) opens a text clip in an editor; "Save as new clip" (or Ctrl+Enter) creates a new clip that goes through the same rules as a copy: a secret is dropped or masked as your sensitive-content setting says (the editor stays open and says why), disabled kinds and the text size limit apply. The original clip never changes. Markdown conversion is not included.

### Added (Phase 2 Windows capture)
- Developer binary `dark-clipboard --headless` (Windows): runs the capture actor on the real Windows clipboard until Ctrl+C, with a content-free size-capped log. No UI yet.
- `App::capabilities()`; the Windows adapter reports read, write and privacy-marker support as native (real-clipboard tests ran in Task 107, see `docs/testing/platform-checklist.md`).
- The headless log records, on stop, one line of skip counts per reason (static reason names and numbers only).
- When storage is full, the capture actor runs retention once and retries the insert once before reporting the failure.
- Check rule S-10: log and print lines in the headless binary may not mention content-like words.

### Added (Phase 1 Foundation)
- Portable Rust workspace: `darkclip-core` (models, capture policy and privacy markers, classification and hashing, sensitive-data detection, i18n en/vi), `darkclip-platform` (adapter traits, capabilities, fake platform), `darkclip-storage` (SQLite + FTS5 with accent-insensitive search, content-addressed blobs, retention, migrations), `darkclip-app` (single capture actor, Application API, settings). Headless only: no OS adapter or UI yet.
- Quality gates: banned-crate, privacy-boundary and logging checks; cargo-deny.

### Fixed
- A `settings.json` that starts with a UTF-8 byte order mark (written by Notepad or PowerShell 5.1) is no longer treated as corrupt (it was renamed and all settings were reset); saving never writes a BOM.
- Windows: clipboard writes through OLE with a flush (for example Notepad) keep their source app, and an excluded app without privacy markers that writes this way is now skipped (F-14). Fixed in the capture actor; real-clipboard recheck pending.
- Windows: a screenshot-sized bitmap copy (for example 4K, offered only as a DIB) is stored when its PNG fits the image size limit; the limit applies to the stored PNG, and bitmap input is bounded separately (64 megapixels, 256 MiB decoded). Real-clipboard recheck pending.
- Windows: copying back a stored image too large to decode safely now puts the PNG alone on the clipboard instead of decoding it; a copy-back retried while the clipboard is busy converts the image once, and its converted data is dropped when the copy-back fails. Real-clipboard recheck pending.
- A clipboard change that replaced another before capture looked at it is no longer stored with the earlier app as its source.

### Known issues
- Almost every Windows UI behaviour is untested by hand: the rows in `docs/testing/platform-checklist.md` for the tray, popup, paste, history window, welcome and start at login are all **untested** (owner manual rows). Automated tests and script measurements cover the logic, not the real desktop.
- The popup open time was measured only through `--toggle` (IPC); the real-shortcut timing, Vietnamese input methods, mixed-DPI monitors and 10,000-clip scrolling are owner manual checks.
- Paste into the previous app is untested on a real desktop: Notepad, VS Code, Edge, Word, an elevated Notepad and a tray-opened popup are owner manual checks. A popup opened from the tray records the taskbar as the previous window, so there Ctrl+Enter only copies. A paste refused after the target already took the focus is not shown (the popup has closed); the clip stays on the clipboard. The popup may show a taskbar button while open.
- Windows build uses the GUI subsystem (no console window). Interactive cmd and PowerShell do not wait for `dark-clipboard --toggle`, `--quit` or `--help`: output may appear after the prompt and `%ERRORLEVEL%` / `$LASTEXITCODE` are not the real exit code (use `start /wait` or `Start-Process -Wait`). `--headless` started from Explorer has no console or tray and stops only via Task Manager: `--quit` does not reach a headless run (it has no instance pipe).
- The history window context menu is mouse only (its entries are not keyboard-focusable); every action also has a key.
- If Explorer restarts, the tray icon may vanish until the app restarts.
- If selecting the software renderer fails, the app logs `renderer_fallback`, but Slint may then fail to start too.
- The confirmation text for removing a built-in excluded app says copies will be stored again, which is not true for the Darkshot entry (its markers still exclude it). `darkshot.exe` became a built-in exclusion in Task 207; existing settings files are not migrated.
- Windows verification covered KeePassXC 2.8.0 and Darkshot; Bitwarden, 1Password, Office and RDP are untested.
- macOS and Linux behaviour is untested, and there is no app for them yet.
