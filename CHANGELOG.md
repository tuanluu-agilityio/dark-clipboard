# Changelog

All notable changes to Dark Clipboard, newest first. Versions follow [SemVer](https://semver.org/). Sections per release: Added, Fixed, Known issues.

## [Unreleased]

### Added

The popup's settings and close icons are Lucide icons with tooltips. No layout changed yet; the redesign of each window follows.
- Task 710: new app icon (a clipboard on the dark tile, shared with Darkshot) for the exe, the taskbar and Alt+Tab, the window title bars and the tray. The tray keeps the same icon and adds a small coloured badge for paused or off (amber), private (grey) and capture unavailable (red).

## [0.1.0] - 2026-11-24

First release: Windows x64 only, alpha, unsigned. macOS and Linux have no app yet.

### Added

- Task 201: `dark-clipboard` with no flag starts the Slint app hidden (always dark, English and Vietnamese; the OS language is used on first run). Single instance per user: a second start forwards its command over a named pipe restricted to the current user and exits 0. New `--toggle` (show or hide the popup), `--quit` and `--help`; `--headless` is unchanged. The licence is GPL-3.0-only (Slint's GPLv3 option).
- Task 202: tray icon (glyphs generated in code for capturing, paused, private and capture off) with tooltip and menu: Pause (5 minutes, 1 hour, until resumed), Resume, Private mode, History, Settings, Quit. Pause and private mode apply at once.
- Task 203: global shortcut, default `Ctrl+Shift+V` (`shortcuts.toggle_popup`; Ctrl, Alt or Win required). A failed registration shows a warning and is not retried until the setting changes or the app restarts. Hidden test flag `--no-global-shortcut`.
- Task 204: the popup. A frameless, always-on-top dark window opens near the cursor on the monitor under it (per-monitor DPI aware) with the search box focused and recent clips listed, pinned first. Search as you type (accent-insensitive, matched words highlighted); filter chips for kind, pinned, today, 7 days and source app; more clips load as you scroll. Keys: arrows, Page Up/Down, Home/End, Enter copies back, Shift+Enter copies plain text, Delete removes with a 5 second Undo toast, Ctrl+P pins, Alt+1..9 copies the n-th result, Esc or clicking elsewhere closes; every action also has a button. Developer flag `--seed-demo-clips N --data-dir <dir>` writes N synthetic clips (never into the default data folder). Popup open time is logged content-free (`perf`); `scripts/measure-popup.ps1` reports p50/p95.
- Task 205: copy back and paste. Enter puts the clip on the clipboard, closes the popup and returns the focus to the window you were in. Ctrl+Enter also pastes it there (Ctrl+V through `SendInput`); the setting `ui.enter_pastes` ("Enter also pastes", off by default) makes Enter paste too. The paste is never blind: it happens only if the window recorded when the popup opened still exists, belongs to the same process, is a normal visible top-level window (never the taskbar, the desktop or a tool window), takes the focus, and Shift/Alt/Win/Enter are released; otherwise the clip stays copied and a toast says "Copied - paste manually". A target running as administrator gets no input and its own toast. The log records only a coarse `paste` outcome (ok, refused, elevated, failed).
- Task 206: previews and details. Image thumbnails and a detail pane for text (first 32 KiB), images and file lists. Content is read only through UI-only calls that re-check the clip before showing it; masked clips never show or keep content.
- Task 211: history window (tray "History..." or Ctrl+H in the popup): filters (pinned, kind, time, source app), search, multi-select (Ctrl/Shift click, Space, Ctrl+A), copy, copy as plain text, pin, delete with a confirmation, detail pane, size and position remembered per monitor layout, context menu (mouse only).
- Task 207: settings window (General, Privacy, History, About): shortcut, language, start at login, close on focus loss, "Enter also pastes", capture mode (normal, private, paused), retention limits (lowering a limit asks first), excluded apps (built-in entries removable only after a confirmation), a text-only row for the OS and Darkshot privacy markers (not configurable), About with licence notices. One Save for the form. `darkshot.exe` is a built-in Windows exclusion.
- Task 208: first-run welcome. A fresh install captures nothing until the user presses Start; "Not now", Esc or X keep capture off; the tray ("Start capturing...") and Settings reopen the welcome. Existing settings files skip it. Start at login through the `DarkClipboard` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (off by default; never touched by a `--data-dir` instance; an entry disabled in Task Manager is shown as off). `--headless` on a fresh data folder stays off and logs `capture_off`.
- Task 212: on Windows the UI uses Slint's software renderer by default (measured about 12 MiB private bytes after use and no idle CPU, against about 72 MiB and 0.2 % of a core with the GPU renderer). A user-set `SLINT_BACKEND` still wins. The start log records `renderer=software|default|env`. Popup open time (`perf what=popup_shown`) is timed from the first redraw after the show request; a new content-free `perf what=search_done ms=<n>` times a typed search.
- Task 200 (internal): `capture.rs` split into a `capture/` directory, with the privacy checks moved to match.
- Task 412: opt-in update check (D-057), the only network code in the app. Settings > About has a "Check for updates" button and an "Automatically check weekly" toggle (off by default; `updates.auto_check` and `updates.last_check_ms` in `settings.json`). A check is one HTTPS GET to `api.github.com/repos/tuanluu-agilityio/dark-clipboard/releases/latest` with only `User-Agent: DarkClipboard/<version>` and `Accept: application/vnd.github+json`: no clip data, settings, identifiers or cookies, no redirects (the proxy variables `HTTPS_PROXY`, `HTTP_PROXY` and `ALL_PROXY` are honoured, the Windows system proxy is not), 10 s timeout, response capped at 256 KiB, only `tag_name` and `html_url` read. The result is "You are up to date" or "New version available: X" (X is rebuilt from the parsed version; tags over 64 bytes or with invalid build metadata are refused) with a button that opens the release page (only an address under `github.com/tuanluu-agilityio/dark-clipboard/releases/tag/`, never a download); only one check runs at a time; with a read-only settings file the toggle is disabled; nothing is downloaded or installed. It runs on a background thread, errors are content-free ("Could not check"), and with the toggle off the app makes no request unless the button is pressed. The HTTP client is `ureq` with rustls (no OpenSSL); the quality gate now fails if any crate under `crates/` depends on an HTTP or TLS client, or if network APIs appear outside `apps/desktop/src/update.rs`.
- Task 403: organisation in the windows. History window: a left pane with Favorites, your collections and your tags (with counts) that filter the list; create, rename and delete collections (delete asks first and keeps the clips); a details strip with the favorite star, the note (up to 4,000 characters with a counter, Save and Cancel) and the tags as chips (an invalid tag shows a message); multi-select actions (favorite or unfavorite, add to or remove from a collection, add a tag) whose confirmation shows the count; every action has a key (`Ctrl+D`, `Ctrl+N`, `Ctrl+G`, `Ctrl+L`, `Ctrl+Shift+L`, `Ctrl+Shift+N`, `Ctrl+Shift+R`, `Ctrl+Shift+Del`), a button and a menu entry. Popup: a star on favorite rows, Favorites and collection filter chips, and `Ctrl+D` to toggle the favorite of the selected row. Masked clips offer no add action (D-060). Snippets are documented as a collection plus pinned clips (no template engine, D-037). The dialogs and the pane are cleared when the window closes.
- Task 404: local text transforms and edited copies. "Copy as..." (Ctrl+T, or the button) in the popup and the history window shows the result of a transform before you copy it: trim (whole text or each line), line endings (LF or CRLF), UPPER or lower case, JSON pretty or minified (up to 1 MiB, nesting up to 128; keys, numbers and escapes are kept as they are), URL percent-encode or decode, Base64 encode or decode (the decoded bytes must be text), and HTML to text (tags removed, script and style content dropped, common entities decoded, paragraphs and list items become lines). Copying the result writes it to the clipboard as Dark Clipboard's own write: it is not captured again and no clip is stored. Input over 1 MiB is refused, never cut. Images, files and masked clips have no "Copy as...". "Edit..." (Ctrl+E, or the button, history window) opens a text clip in an editor; "Save as new clip" (or Ctrl+Enter) creates a new clip that goes through the same rules as a copy: a secret is dropped or masked as your sensitive-content setting says (the editor stays open and says why), disabled kinds and the text size limit apply. The original clip never changes: saving text that is already in history touches nothing and shows "Already in history" (and selects that clip); saving is refused in private mode and allowed while paused. Transform output over 1 MiB is refused. Markdown conversion is not included.
- Task 405: backup, restore, export and import. Settings > History > Backup and transfer: "Back up now..." writes a `.dcbackup` zip (a consistent `history.db` snapshot without masked or expired clips and without free pages, the blob files it references, and `manifest.json` with format, schema version, app version, date, clip count and the size and SHA-256 of every file) through a temporary file named `<file>.dark-clipboard-partial` that is renamed when complete. A backup is a plain, unencrypted zip. Backups and exports that their own reader would refuse (too many or too large files) are not written. "Restore from backup..." asks first, then validates the whole file before touching anything: only `manifest.json`, `history.db` and `blobs/<aa>/<sha256>` entries (no absolute paths, `..`, drive letters, directories, symlinks, duplicate names or encryption), entry count, declared total and size limits counted while decompressing, a compression ratio above 200:1 (above 64 MiB) refused, every file's size and SHA-256, and a newer format or schema refused with its own message. The database is checked before any migration on a defensive connection (UTF-8 only; `integrity_check`; `user_version` equal to the manifest's; the whole unfiltered `sqlite_master` equal to a schema this app created, so an object planted under any name is refused; only SQLite's own `sqlite_sequence`, `sqlite_stat1` and `sqlite_stat4` tables with SQLite's exact SQL are allowed besides it), opened in a private staging folder (migrations run) and must pass `foreign_key_check` and a decode of every clip. Header fields the SQLite backup API copies (page size, auto-vacuum, application id, journal mode) are normalised to the live database. A restore checks free disk space first, copies the live data to `history.db.pre-restore-<ms>` (kept until the next start) and replaces it through SQLite's online backup API on the single writer connection, inside one write transaction that is rolled back on any failure. A restored history is not re-scanned for sensitive content. Import of `.dcexport` files re-derives kind, preview, hash and sensitivity through capture's own rules, drops sources, platform format names, pin state and counters, clamps dates to now, checks the size limits (the declared size of each blob before it is read; a blob shared by several clips counts once), skips file lists, merges duplicates (bump, no second row), and reports counts per reason; it is refused in private mode. Export (history window, `Ctrl+Shift+E`: the shown collection or the marked clips; `export_collection` for the UI under `<data>/exports/`) writes `export.json` matching `export.schema.json` plus one blob per representation, never masked or sensitive clips (the result counts them), never sources. Clips captured with the Windows `CanUploadToCloudClipboard` = 0 marker (NoCloud) are flagged (schema migration 3, `clips.no_export`, sticky on later copies) and never exported; backups keep them; clips captured before carry no flag; imports never set it. The file picker is the Windows shell dialog, on its own thread. Backups, restores, exports and imports do not occupy the app's worker: they are waited for on their own thread, and the capture actor handles every queued message in order before it acts on a due clipboard change, so a mode change made meanwhile applies before any later clipboard change. New dependency: `zip` 9.0 (deflate only).
- Task 411: Settings > History shows storage usage (clips, pinned, favorites, database size, blob size, clips per kind) and cleanup tools, each with a confirmation that names the count: clear history now keeps pinned clips **and favorites** (unticking the box deletes everything), delete clips older than N days (pinned clips and favorites are kept), remove orphaned blob files now (reports files and bytes freed) and compact the database (`VACUUM`; refused when free disk space is below twice the database size or cannot be measured). F-20: deleting clips by hand, clearing, deleting old clips, compacting and re-capturing a clip as masked now merge the contentless search index (`optimize`) and truncate the write-ahead log at once, so the words no longer linger in `history.db`. Clips evicted automatically by the retention limits, and note or tag changes, only mark the index dirty: it is merged every 10 minutes, at start, at shutdown and after 100 pending changes, so those words leave the file within about 10 minutes (a merge after every capture cost 140-260 ms at 10k clips). Compact keeps its temporary files in memory (no copy of the history in the system temp folder) and needs free disk space of twice the database size. `Storage::sweep_orphan_blobs` is unchanged; the new `sweep_orphans` reports bytes too.
- Phase 0 blueprint: product vision, feature matrix, MVP scope, user journeys, system architecture, platform capability matrix, data model with JSON Schemas and examples, threat model, privacy design, AI/MCP interface draft, ADR-0001 to ADR-0006, roadmap and Phase 1–5 plans, Phase 1 task packages.
- Feasibility spikes on Windows (clipboard monitoring; Tauri 2 vs Slint shell). These are throwaway code under `spikes/`.
- Agent workflow (`CLAUDE.md`, `AGENTS.md`, `.claude/`), memory-bank, quality gate scripts, CI workflow.
- Developer binary `dark-clipboard --headless` (Windows): runs the capture actor on the real Windows clipboard until Ctrl+C, with a content-free size-capped log.
- `App::capabilities()`; the Windows adapter reports read, write and privacy-marker support as native (real-clipboard tests ran in Task 107, see `docs/testing/platform-checklist.md`).
- The headless log records, on stop, one line of skip counts per reason (static reason names and numbers only).
- When storage is full, the capture actor runs retention once and retries the insert once before reporting the failure.
- Check rule S-10: log and print lines in the headless binary may not mention content-like words.
- Portable Rust workspace: `darkclip-core` (models, capture policy and privacy markers, classification and hashing, sensitive-data detection, i18n en/vi), `darkclip-platform` (adapter traits, capabilities, fake platform), `darkclip-storage` (SQLite + FTS5 with accent-insensitive search, content-addressed blobs, retention, migrations), `darkclip-app` (single capture actor, Application API, settings).
- Quality gates: banned-crate, privacy-boundary and logging checks; cargo-deny.
- Docs: the user guide `docs/user/windows-alpha.md` now covers 0.1.0, `README.md` has a download and status section, `docs/release.md` describes the release workflow and [`docs/user/release-notes-0.1.0.md`](https://github.com/tuanluu-agilityio/dark-clipboard/blob/v0.1.0/docs/user/release-notes-0.1.0.md) is the page the release body links to.

### Fixed

- F407-01: crash reports no longer carry clip memory to Windows Error Reporting. At every start, in every run mode and before capture starts, the app calls `WerAddExcludedApplication(<exe name>, FALSE)` (per-user exclusion, `HKCU`) and `WerSetFlags(WER_FAULT_REPORTING_FLAG_NOHEAP)`. A failure is logged (`wer_failed excluded=... no_heap=...`) and start-up goes on.
- F407-02: the data folder (default or `--data-dir`) gets a protected DACL at start: full control for the current user and SYSTEM only, inherited by every file and folder in it. Applied only to the default folder or a folder the app created itself, which it marks with a `.dark-clipboard-data` file; a `--data-dir` folder that existed before is never changed, even once it holds a `history.db` (`data_dir_acl result=not_ours`). The folder's owner must be the current user, or `BUILTIN\Administrators` when the app runs elevated (the default owner then); otherwise `not_owner`. A failure is logged and start-up goes on. The log records the time taken (`ms=`): the first start on an existing install rewrites the access list of every file below the folder, on the main thread before the UI appears.
- F407-03: a history that cannot be opened no longer makes the app quit silently. The database is checked at open (`PRAGMA quick_check`, both connections); a damaged file or one that is not a database is reported as damaged. The app shows a message window with the data folder: a newer history is only explained and never touched; a damaged one can be moved aside (renamed with the mark `damaged-<ms>`, together with its `-wal`/`-shm` files, the `blobs` folder and any pre-migration or pre-restore copies; nothing is deleted) and the app starts with an empty history. The moved-aside files keep all old clips, including ones that would have expired; retention and Clear history do not touch them, and the message and the README say so and name them. `--headless` prints the explanation and never moves anything.
- F407-04: if another program holds the app's connection (named pipe) name, the app says "Dark Clipboard could not start: another program is using its connection." instead of quitting silently. A name that is taken is tried again for about a second first, so an instance started right after the previous one quit is not mistaken for a squatter.
- F407-05: Settings and the README say that a backup is a plain, unencrypted zip that keeps every clip except masked and expired ones, including clips apps asked not to sync, and that saving it in a synced folder uploads it.
- F407-08: KeePass 2 (`keepass.exe`) is a built-in excluded app on Windows (new settings files only; an existing settings file keeps its list). Not yet tested with a real KeePass 2.
- F407-11: `darkclip-platform`, `darkclip-storage` and `darkclip-app` forbid `unsafe` code; `darkclip-core` denies it outside its zeroing module.
- A `settings.json` that starts with a UTF-8 byte order mark (written by Notepad or PowerShell 5.1) is no longer treated as corrupt (it was renamed and all settings were reset); saving never writes a BOM.
- Windows: clipboard writes through OLE with a flush (for example Notepad) keep their source app, and an excluded app without privacy markers that writes this way is now skipped (F-14). Fixed in the capture actor; real-clipboard recheck pending.
- Windows: a screenshot-sized bitmap copy (for example 4K, offered only as a DIB) is stored when its PNG fits the image size limit; the limit applies to the stored PNG, and bitmap input is bounded separately (64 megapixels, 256 MiB decoded). Real-clipboard recheck pending.
- Windows: copying back a stored image too large to decode safely now puts the PNG alone on the clipboard instead of decoding it; a copy-back retried while the clipboard is busy converts the image once, and its converted data is dropped when the copy-back fails. Real-clipboard recheck pending.
- A clipboard change that replaced another before capture looked at it is no longer stored with the earlier app as its source.

### Known issues

- **Windows only.** There is no macOS or Linux app: their clipboard adapters do not exist yet (Phase 4). Nothing is claimed for them. Windows 10 is untested; the checks ran on one Windows 11 machine.
- **Unsigned.** The binary has no Authenticode signature; Windows SmartScreen may warn. Every release file has a SHA-256 in `SHA256SUMS.txt`, which protects against a damaged download, not against a different builder.
- **Alpha: the desktop UI is untested by hand.** Almost every UI row (tray, real shortcut, popup keys, paste into other apps, elevated targets, history and settings windows, welcome, start at login, mixed-DPI monitors, Vietnamese input methods, screen readers, and the screens of Tasks 403, 404, 405, 411 and 412) is an owner manual row marked `untested` in `docs/testing/platform-checklist.md`. The logic behind the screens is covered by automated tests. The popup open time was measured only through `--toggle` (IPC); the real-shortcut timing, mixed-DPI monitors and 10,000-clip scrolling are owner manual checks. Paste into the previous app (Notepad, VS Code, Edge, Word, an elevated Notepad, a tray-opened popup) is untested on a real desktop; a popup opened from the tray records the taskbar as the previous window, so there Ctrl+Enter only copies; a paste refused after the target already took the focus is not shown (the popup has closed) and the clip stays on the clipboard; the popup may show a taskbar button while open.
- **Search speed.** The search benchmark is around its 30 ms budget on a busy machine (F-21): over five runs the worst-case 95th percentile was 29.1 to 32.0 ms (3 of 5 runs over the 30 ms budget) and the realistic one 22.2 to 30.4 ms (1 of 5 over). The machine was not idle; not re-measured on an idle machine.
- **libFuzzer targets have never been run (F-24).** The parsers' bounds are covered by ordinary tests only.
- **KeePass 2 exclusion only for new settings files.** `keepass.exe` is a built-in excluded app only in a settings file created by this version; an existing settings file keeps its own list (add it in Settings > Privacy). It has not been tested with a real KeePass 2. App identity is cooperative (F-09), so the clipboard markers remain the main defence.
- **Bitwarden and 1Password are untested (R-02).** They are in the built-in exclusion list but were never run on a real clipboard. Only KeePassXC 2.8.0 and Darkshot 0.6.0 were verified. Word, Excel and Remote Desktop clipboard sources are untested too.
- **File dialogs are Windows only.** Backup, restore, export and import use the Windows shell file dialog; it is compiled but was never run by hand.
- **Older `--data-dir` folders keep their old access list.** A `--data-dir` folder that existed before 0.1.0 does not get the private access list, and neither does any folder the app did not create (it leaves a `.dark-clipboard-data` marker in the ones it did). The default data folder does get it.
- **Backups are not encrypted.** A `.dcbackup` is a plain zip that holds every clip except masked and expired ones, including clips apps asked not to sync; keep it out of synced folders.
- **Crash-report exclusion is unverified by hand.** The Windows Error Reporting exclusion (F407-01) and the data-folder access list (F407-02) were added in Task 413 and their manual rows (the registry value, `icacls`) have not been run by hand.
- **Large images.** The peak memory of a very large image capture (64 megapixels) was not measured (F407-09).
- **No console.** The Windows build uses the GUI subsystem. Interactive cmd and PowerShell do not wait for `dark-clipboard --toggle`, `--quit` or `--help`: output may appear after the prompt and `%ERRORLEVEL%` / `$LASTEXITCODE` are not the real exit code (use `start /wait` or `Start-Process -Wait`). `--headless` started from Explorer has no console or tray and stops only via Task Manager: `--quit` does not reach a headless run (it has no instance pipe).
- **History window context menu is mouse only** (its entries are not keyboard-focusable); every action also has a key.
- **Explorer restart.** If Explorer restarts, the tray icon may vanish until the app restarts (F-17).
- **Renderer fallback.** If selecting the software renderer fails, the app logs `renderer_fallback`, but Slint may then fail to start too.
- **Misleading confirmation text.** The confirmation for removing a built-in excluded app says copies will be stored again, which is not true for the Darkshot entry (its markers still exclude it). `darkshot.exe` became a built-in exclusion in Task 207; existing settings files are not migrated.
- **Carried over from the security review.** The identity of the app that owns the clipboard is not authenticated, so an excluded-app rule can be fooled (F-09); the actor's post-message drain is unbounded and a restored `sqlite_stat1` is accepted (F-23).
