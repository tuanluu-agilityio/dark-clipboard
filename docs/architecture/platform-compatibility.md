# Platform Compatibility and Capability Matrix

Status: Phase 0, 2026-11-22.

Evidence legend (every cell carries one):

- **T**: tested on a real machine: Phase 0 spikes (`docs/spikes/`) or later verification runs (`docs/testing/platform-checklist.md`). Windows **T** means Windows 11 10.0.26300 only; Windows 10 is untested.
- **D**: documented by the platform vendor or project; not yet tested by us.
- **R**: reported by third parties (issue trackers, blogs); conflicting or unconfirmed.
- **?**: unknown; must be tested before any claim.

Phase 0 test environment: one machine, Windows 11 Home 10.0.26300, x64, Rust 1.100.0. **No macOS machine and no Linux machine or WSL were available.** Every macOS and Linux cell is therefore D, R or ?.

## 2. Phase 0 test results (Windows)

Source: `spikes/win-clipboard-monitor/spike-output-2026-11-22.txt`, write-up in `docs/spikes/windows-clipboard-monitor.md`.

| Scenario | Result |
|---|---|
| S1 plain text, same process | 1 event, 4.7 ms after write, owner exe identified |
| S2 text + Darkshot's three exclusion formats | 1 event; all three markers detected during enumeration; content not read |
| S3 only `CanIncludeInClipboardHistory=0` | detected, content not read |
| S4 `CF_DIB` image | 1 event; OS synthesized `CF_BITMAP` and `CF_DIBV5` |
| S5 burst of 20 writes in 239 ms | 20 events delivered, only 2 distinct sequence numbers visible at handling time → dedupe by sequence number; intermediate contents are lost (accepted) |
| S6 text from PowerShell (OLE) | 3 events per copy: first with only `DataObject`/`Ole Private Data`, second with text (needed 4 open attempts due to contention), third after flush with owner = none |
| S7 file list from PowerShell | same 3-event pattern; `CF_HDROP` + `FileNameW` |
| S8 self-write suppression | post-write sequence number equals the notified one → suppressible |

## 2b. Phase 2 verification results (Windows, 2026-11-22; Changed by D-041)

Recorded in `docs/testing/platform-checklist.md`; Windows 11 10.0.26300 only. With the Phase 2 adapter and `dark-clipboard --headless`, these Windows cells of §1 are now **T**:
- Rich text: `HTML Format` (Chrome 158) only; `Rich Text Format` stays **D**.
- Images: registered `PNG` (Snipping Tool) and a Windows-synthesised `CF_DIBV5` (automated).
- File lists: `CF_HDROP` (Explorer).
- Concealed/private markers: proven end to end by Darkshot 0.6.0 Copy image and Copy link (owner none, so only the markers could cause the skip). KeePassXC 2.8.0 markers observed in the format list on at least one copy; its skip path was not recorded. Snipping Tool's allowing DWORD values are read and do not skip.
- Write clipboard: copy-back with post-close sequence suppression (automated).
- Source application: owner resolution at signal time **T** (powershell.exe, automated). Stored source **T** for chrome.exe, explorer.exe, SnippingTool.exe; **F** for OLE-flush writers whose final phase has no owner (Notepad, PowerShell): F-14.

Not tested: Bitwarden, 1Password, Office, RDP, elevated source, Win+V after copy-back (manual), Windows 10.

## 3. Known restrictions and design responses

| Restriction | Response |
|---|---|
| Wayland: no portable clipboard monitoring without data-control | Backend probe at startup: `ext-data-control-v1` → `zwlr-data-control-unstable-v1` → X11 via XWayland (only if `DISPLAY` set and the user opts in; XWayland only sees X11 clients' copies) → `Unavailable` state shown in UI and tray |
| GNOME Wayland | Not promised. Phase 4 runs a real test on the current Fedora/Ubuntu GNOME. If ext-data-control is present, it is supported; if not, the app shows "capture unavailable" and links to docs. No Shell extension in P0 (CopyQ's experience shows packaging limits) |
| macOS pasteboard privacy prompt | Phase 4 spike on macOS 26: measure whether polling `changeCount` alone prompts (expected: no, it reads no content) and whether reading `string(forType:)` prompts when the setting is "Ask". Use `NSPasteboard.detect*` / type queries before reading content. Document the one-time grant in onboarding |
| macOS no notification | Poll `changeCount` every 300 ms on a background thread (Maccy-style). Each poll reads one integer and no content. Adaptive back-off based on user input is not planned, because it would need the Input Monitoring permission |
| Windows UIPI | Auto-paste into elevated windows fails silently; detect with `GetWindowThreadProcessId` + token elevation check and fall back to copy only with a toast |
| Windows OLE delayed rendering | Debounce 75 ms; capture source at first signal; skip snapshots whose only formats are `DataObject`/`Ole Private Data` |
| Clipboard locked by another app | Retry open 10 × 20 ms; then drop this change (log code only) |
| Remote Desktop clipboard redirection (`rdpclip.exe`) | Treated as a normal source; can be excluded by app rule; untested (**?**) |
| X11 selection ownership on write | Linux adapter keeps a selection-owner thread alive while Dark Clipboard owns CLIPBOARD; on exit hand over to a clipboard manager if `CLIPBOARD_MANAGER` exists (ICCCM `SAVE_TARGETS`) |
