# ADR-0004: Platform abstraction and capability model

- Status: **Accepted**, 2026-11-22

## Decision

`darkclip-platform` defines OS-independent traits and a capability report. Adapters implement them. A `FakePlatform` in the same crate drives all tests of `darkclip-app`.

```rust
pub struct Capabilities {
    pub monitor: Support,            // Native | Polling { interval_ms } | Unsupported { reason }
    pub read_without_focus: Support,
    pub write: Support,
    pub concealed_markers: Support,  // can the adapter see OS/app privacy markers before content?
    pub source_app: SourceSupport,   // Owner | Frontmost | None
    pub global_shortcut: ShortcutSupport, // Native | Portal | UserBound
    pub auto_paste: Support,
    pub tray: Support,
    pub autostart: Support,
    pub backend: &'static str,       // "win32", "appkit", "x11-xfixes", "ext-data-control-v1", ...
}

pub trait ClipboardMonitor: Send {
    /// Starts the platform event source; sends a signal for every observed change.
    fn start(&mut self, tx: std::sync::mpsc::Sender<ChangeSignal>) -> Result<(), PlatformError>;
    fn stop(&mut self);
}

/// All methods are called only from the CaptureActor thread (not Sync on purpose).
pub trait ClipboardAccess: Send {
    fn sequence(&self) -> Result<u64, PlatformError>;
    /// Format names, markers and source. Must not read content.
    fn snapshot_meta(&mut self) -> Result<ClipboardMeta, PlatformError>;
    /// Reads only the formats in the plan, enforcing per-format byte caps.
    fn read(&mut self, plan: &ReadPlan) -> Result<Vec<RawRepresentation>, PlatformError>;
    /// Writes representations; returns the sequence number after the write (self-write suppression).
    fn write(&mut self, reps: &[RawRepresentation]) -> Result<u64, PlatformError>;
}

pub trait PasteInjector: Send { fn paste(&mut self, target: &PasteTarget) -> Result<(), PlatformError>; }
pub trait SourceResolver: Send { fn resolve(&self) -> Option<ClipboardSource>; }

pub struct ClipboardMeta {
    pub seq: u64,
    pub formats: Vec<PlatformFormat>,       // name + normalized mime if known
    pub markers: Vec<PrivacyMarker>,        // OsConcealed(name) | DarkshotExcluded | Transient | AutoGenerated | PasswordManagerHint
    pub source: Option<ClipboardSource>,
}

pub enum PlatformError { Unsupported(&'static str), PermissionDenied(&'static str), Busy, TooLarge { format: String, bytes: u64 }, Backend { code: i64 } }
```

`PrivacyMarker` mapping per platform is specified in `docs/security/privacy-design.md` §3 and unit-tested in each adapter (pure mapping functions, testable without the OS).

Each adapter crate exposes `fn create() -> Result<PlatformBundle, PlatformError>` returning the boxed trait objects plus `Capabilities`. `apps/desktop` picks the adapter by `cfg`; Linux picks the backend at runtime by probing.

## Rules

1. Adapters contain no policy: they report markers, they never decide to skip. Policy lives in `darkclip-core::policy` (pure, tested). There is one exception: an adapter must not call `read` for formats absent from the plan.
2. `ClipboardAccess` is `Send` but not `Sync`: only the actor thread touches it.
3. `Unsupported` is a normal value. The UI renders capabilities, and features hide or degrade, never crash.
4. Adapters implement `Debug` without content; raw buffers are zeroized (`fill(0)`) after conversion when the format is text (cheap defence in depth, Darkshot `wipe` pattern).

## Alternatives

- One trait with everything (`Platform`): rejected; the monitor runs on its own thread, the access methods do not.
- Async traits: rejected; clipboard APIs are synchronous and thread-affine (Win32 window thread, AppKit main thread).
