# Privacy Design

> Changed by D-044 (2026-11-23): `crates/darkclip-app/src/capture.rs` was split into the module directory `crates/darkclip-app/src/capture/`; every reference to `capture.rs` in this document means that directory. The no-logging rule also covers `image.rs` and the OS adapter crates (D-043).

Status: Phase 0, 2026-11-22. Companion to `threat-model.md`. User-facing promise style follows Darkshot: we say "best effort" for detection and never "guarantee".

## 1. Promises (user-facing, P0)

1. No account. No cloud. No telemetry. Works offline.
2. Content that your OS or app marked private is never stored. This includes password managers that use the standard markers and Darkshot's own copies.
3. You decide what is kept: pause, private mode, excluded apps, retention limits, delete anything.
4. Logs never contain what you copied.
5. AI tools see nothing unless you grant access, and only what the grant allows.

## 2. Decision pipeline (order matters; first match wins)

| # | Check | Input used | Reads content? | Result |
|---|---|---|---|---|
| 1 | Capture disabled / private mode / paused | settings | no | `Skip(Paused|Private)` |
| 2 | Self-write (sequence equals our last write) | seq | no | `Skip(SelfWrite)` |
| 3 | Mandatory markers (§3) | format list | no (Windows DWORD markers are read; they are not content) | `Skip(OsConcealed|DarkshotExcluded)` |
| 4 | Transient / auto-generated markers | format list | no | `Skip(Transient)` |
| 5 | Excluded app | source | no | `Skip(ExcludedApp)` |
| 6 | Kind not enabled (`capture_kinds`) | format list | no | `Skip(KindDisabled)` |
| 7 | Size caps | sizes where known | no | `Skip(TooLarge)` or truncate text |
| 8 | Read | plan | **yes** | representations |
| 9 | Sensitive detection (secondary) | text | yes, in memory | `drop` (default) → `Skip(Sensitive)`; `store_masked` → masked preview, no FTS body, `expires_at = now + ttl`; `store` → stored with category flags |
| 10 | Dedupe and store | hash | — | stored |

The function `policy::decide_pre_read` (steps 1–7) is pure, in `darkclip-core`, and covered by table-driven tests. `check.ps1` asserts that the adapter's `read` is called only from `darkclip-app/src/capture.rs`, right after a `Read` decision (static check, Darkshot `privacy_gate` style).

## 3. Marker mapping

| Platform | Marker (exact) | Maps to |
|---|---|---|
| Windows | `ExcludeClipboardContentFromMonitorProcessing` (any data) | `OsConcealed` (mandatory) |
| Windows | `CanIncludeInClipboardHistory` with DWORD 0 | `OsConcealed` (mandatory) |
| Windows | `CanUploadToCloudClipboard` with DWORD 0 alone | **not** a skip (means "do not sync", not "do not store"); recorded as `NoCloud` and forces the clip to never be exported or synced (P3) |
| Windows | Darkshot set = the three formats above together | `DarkshotExcluded` (reported separately for stats; same effect) |
| Windows | `Clipboard Viewer Ignore` | `OsConcealed` (convention used by several managers) |
| macOS | `org.nspasteboard.ConcealedType` | `OsConcealed` |
| macOS | `org.nspasteboard.TransientType` | `Transient` |
| macOS | `org.nspasteboard.AutoGeneratedType` | `Transient` |
| macOS | `com.agilebits.onepassword` (1Password legacy type; **unverified**, confirm in Phase 4) | `OsConcealed` |
| Linux | MIME `x-kde-passwordManagerHint` with content `secret` | `OsConcealed` |

The list is code (one table per adapter) plus tests. Adding to it is a reviewed change; removing an entry requires an ADR.

## 4. Sensitive-data detection (secondary safeguard)

- Categories P0: API keys (known prefixes: `sk-`, `ghp_`, `github_pat_`, `xox[abp]-`, `AKIA`, `AIza`, `glpat-`…), tokens (JWT shape with decodable header), private keys (PEM `BEGIN … PRIVATE KEY`), passwords (value after `password:`/`pwd=`/`mật khẩu:` labels), payment cards (13–19 digits, Luhn). Email and phone are available but off by default (too common in normal copies).
- Rules are hand-written matchers in `darkclip-core::sensitive`, no regex dependency (Darkshot's Privacy Shield did the same). Darkshot's matcher code is **not** copied: it is OCR-oriented. Its test corpus approach (synthetic data, keys assembled at runtime so secret scanners do not fire) is reused.
- The result type contains categories only, never matched text. Temporary buffers are wiped.
- Masked preview format: first 3 visible characters of the matched token + `…••••` + category label, only for `store_masked`.
- Detection is advertised as best effort, with known misses documented.

## 5. Pause and private mode

- **Pause** has a deadline (5 min, 1 h, until resumed). **Private mode** is open-ended and shown prominently (tray icon variant, popup banner).
- In both, the monitor keeps running but the actor drops signals at step 1, without reading formats.
- Resuming does not backfill: the clipboard content present at resume time is **not** captured unless it changes again. This avoids capturing something copied during the pause.

## 6. Excluded apps

- Matching by `app_id` per platform (exe name, bundle id, desktop id), case-insensitive on Windows.
- Unknown source (no owner, Wayland) cannot be matched; the UI says so on Wayland ("app exclusions are not available on this session").
- Built-in defaults (editable, marked `builtin`): KeePassXC, KeePass, 1Password, Bitwarden, Dashlane, Enpass, Keychain Access, Proton Pass, plus Darkshot's executable on Windows (belt and braces; its markers already exclude it).

## 7. Logging rules

- Levels: `error`, `warn`, `info` (default), `debug` (opt-in via settings, auto-off after 24 h).
- Allowed fields: event codes, skip-reason counters, durations, sizes, format names, error codes. In `debug` only: app ids.
- Forbidden always: clip text, previews, file paths from `files` clips, image data, window titles, search queries.
- Enforced by: manual `Debug` impls, a `check.ps1` rule that bans logging macros in capture/sensitive modules, and a test that formats every public model type with `{:?}` and asserts the content is absent.

## 8. Data retention defaults

1,000 items · 30 days · 500 MiB · pinned and favorites exempt · sensitive handling `drop` · images ≤ 20 MiB · text ≤ 1 MiB (truncated beyond).

## 9. AI data access (P2)

See ADR-0005 and `docs/architecture/ai-integration.md`. Summary: off by default, stdio only, scoped grants created in the desktop UI, sensitive never grantable, no filesystem paths accepted, content-free audit, no implicit cloud upload.

## 10. Darkshot interoperability rule

Dark Clipboard must **never** read, store, index, or forward content carrying Darkshot's exclusion markers. No setting, CLI flag, MCP scope or debug mode may change this. Any future Darkshot integration (for example "send image clip to Darkshot") is one-way from Dark Clipboard to Darkshot, and only for clips Dark Clipboard captured legitimately.

## 11. Limits of the static checks (Phase 1 review, D-029)

`scripts/check.ps1`/`check.sh` enforce that `ClipboardAccess` (type, `.access` field, `access:` destructuring) and adapter `read`/`write` calls appear only in allowed files. They do **not** prove the ordering "read only right after a `Decision::Read`". That ordering is proven by tests with the fake platform's counters (`excluded_never_read`, `paused_never_reads_formats`, `paused_passes_no_formats_to_policy`). Reviews of `capture.rs` must re-check it by reading the code.
